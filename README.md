# wasm-opt-cert

This project implements a verified local-coalescing optimisation pass for WebAssembly binaries, it is tailored towards Wasm binaries generated by [CertiRocq](https://github.com/certirocq/certirocq).

The pass is extracted to OCaml and tested on CertiRocq's benchmarks.

### Assumptions
- the WebAssembly binaries are following the Wasm 2.0 standard (and may contain tailcalls)
- binaries are in SSA form, and the control flow is essentially linear
- all locals have the type i32

Unsupported functions remain unchanged.

### Setup and Examples
A setup with nix is recommended:
```sh
nix develop
just foo        # coalesce foo.wasm, then run foo_opt.wasm under node
just sha        # same for sha.wasm (~175KB; the parser takes ~20s)
just sha_check  # sha.wasm + compare_output.py
```

### Correctness

The function `coalesce_module` applies local-coalescing to every function in the module.
Calling any function on the optimized module behaves exactly as calling the
same function on the original.

This composes with CertiRocq's [`toplevel_theorem.v`](https://github.com/CertiRocq/certirocq/blob/main/theories/CodegenWasm/toplevel_theorem.v),
whose `LambdaANF_Wasm_related` runs the program from `Build_frame [] (f_inst fr)` after `instantiate`.

The main statement is `coalesce_module_correct` in [`theories/toplevel_correct.v`](./theories/toplevel_correct.v),
it proves the specification [`theories/toplevel_spec.v`](./theories/toplevel_spec.v):

```coq
Definition call_equiv (s s_opt : store_record) (f f_opt : frame) : Prop :=
  forall a vs hs hs' res,
    terminal res ->
    (forall s',
       reduce_trans (hs, s, f, v_to_e_list vs ++ [AI_invoke a]) (hs', s', f, res) ->
       exists s_opt',
         reduce_trans (hs, s_opt, f_opt, v_to_e_list vs ++ [AI_invoke a])
                      (hs', s_opt', f_opt, res)
         /\ store_visible_eq s' s_opt')
    /\
    (forall s_opt',
       reduce_trans (hs, s_opt, f_opt, v_to_e_list vs ++ [AI_invoke a])
                    (hs', s_opt', f_opt, res) ->
       exists s',
         reduce_trans (hs, s, f, v_to_e_list vs ++ [AI_invoke a]) (hs', s', f, res)
         /\ store_visible_eq s' s_opt').

Definition coalesce_module_correct_statement : Prop :=
  host_ignores_code ->
  forall s m v_imps s_end f bes,
    store_guarded s ->
    instantiate s m v_imps (s_end, f, bes) ->
    exists s_end_opt f_opt bes_opt,
      instantiate s (coalesce_module m) v_imps (s_end_opt, f_opt, bes_opt) /\
      call_equiv s_end s_end_opt f f_opt.
```

- **`host_ignores_code`** - a call to an imported host function neither reads
  the code section nor changes it. `host_application` is an arbitrary *relation*
  in WasmCert that may return any store, so nothing otherwise rules out a host
  that inspects function bodies and behaves differently once a callee's locals
  have been renamed. No proof about the Wasm side can exclude that.
- **`store_guarded s`** - Wasm functions already in the store obey the same
  nesting restriction the pass checks on the code it compiles. They are shared
  by both sides, so the proof has to relate each of them to itself, which needs
  that restriction. The pass only sees the module it is handed, so it cannot
  check them. Immediate when the store holds only host functions, as in CertiRocq.


### TCB
WasmCert's binary parsing and printing are currently unverified and trusted.
We don't introduce any axioms in addition to WasmCert.
```sh
just print_assumptions
```

### LLM usage

The project is completely generated by LLMs, using LLM4Rocq/rocq-mcp.

Initially, I used OpenCode with Deepseek V4 (both pro and flash), GLM 5.1, GLM 5.2.
These models are good enough to prove known-to-be-correct statements from their context.
But they are generally not good enough to overcome obstacles and generalize statements, I used Claude Opus 5 for proofs.
